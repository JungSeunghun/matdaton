# 최종 아이디어: First Move

> 매일 아침 하루의 첫 30분을 90초로 컴파일하는 개인 업무 시동 에이전트

## 1. 한 줄 요약

아침에 `하루 시작` 버튼 하나를 누르면, 밤사이 바뀐 것을 수집하고 오늘의 우선 행동 3개를 제안하며, 승인한 준비 작업을 대신 실행하고 결과를 검증해 **증거 영수증**을 발급하는 웹 앱.

## 2. 문제 정의

### 대상 사용자

GitHub, 캘린더, 메모를 오가며 일하는 개인 지식 노동자·개발자.

### 핵심 문제

매일 아침 업무를 시작할 때 다음을 반복한다.

- 어제 어디까지 했는지 기억 복원
- 밤사이 커밋, 이슈 댓글, 리뷰 요청 확인
- 오늘 일정과 가용 시간 파악
- 무엇부터 할지 결정

이 시동 과정에 **매일 평균 30분**이 소모되며, 요약 도구는 정보를 압축할 뿐 "무엇부터 할지"와 그 준비 작업까지 연결하지 못한다.

### 해결 가설

밤사이 변경과 오늘의 제약을 자동 수집해 우선 행동 3개를 근거와 함께 제시하고, 승인된 준비 작업을 실행·검증하면 아침 시동 시간을 90초 이하로 줄일 수 있다.

## 3. 핵심 사용자 흐름

```text
아침 07:50 — 하루 시작 버튼
├── ① 수집: 밤사이 커밋 3, 이슈 댓글 2, 리뷰 요청 1 + 오늘 회의 2건
├── ② 계획: 실행 계약 컴파일 (우선 행동 3개 + 성공 조건 + 금지 범위)
├── ③ 검사: 위험 행동·프롬프트 인젝션 안전 점검
├── ④ 승인: 드라이런 미리보기 확인, 원치 않는 노드 제외
├── ⑤ 실행: 할 일 2개 생성, 이슈 댓글 초안 1개 (승인된 것만)
└── ⑥ 영수증: 성공 조건 5/5 통과, 시동 시간 84초, 절약 28분
```

사용자 조작은 **버튼 1개 → 승인 1회 → 영수증 확인**의 3단계로 고정한다.

## 4. 에이전트 설계

### Copilot SDK

- 세션과 사용자 컨텍스트 관리
- GitHub 저장소·커밋·이슈·PR 조회 도구 호출
- 구조화된 실행 계약과 우선 행동 출력
- 진행 상태의 웹 UI 스트리밍
- 승인 이후에만 쓰기 도구 실행

### Microsoft Agent Framework — 5개 에이전트 오케스트레이션

| 에이전트 | 역할 | 만점 증거 |
| --- | --- | --- |
| Scout Agent | 밤사이 GitHub 변경과 일정 제약 병렬 수집 | 병렬 fan-out 실행 trace |
| Compiler Agent | 실행 계약과 우선 행동 3개 컴파일 | 구조화 스키마 출력 |
| Policy Agent | 금지 범위·권한·프롬프트 인젝션 검사 | 차단 데모와 감사 로그 |
| Executor Agent | 승인 토큰이 있는 노드만 실행 | 승인 전후 로그 대조 |
| Verifier Agent | 결정적 규칙으로 성공 조건 검증 | 규칙별 통과·실패 영수증 |

```text
Scout(병렬) → Compiler → Policy → 사용자 승인 → Executor → Verifier
```

모든 단계는 하나의 `executionId`로 연결된다.

## 5. 100점을 만드는 4개 장치

1. **증거 자동 생성** — 모든 실행이 시동 시간, 도구 호출, 근거 링크, 성공 조건 결과를 자동 기록. 팀원 4명이 매일 쓰면 심사 시점에 20회 이상의 실측 데이터가 앱 대시보드에 쌓인다.
2. **Judge Mode** — 심사위원이 임의의 공개 GitHub 저장소 URL을 입력하면 그 저장소의 최근 24시간 변경으로 전체 흐름이 즉석 실행된다. 하드코딩 의심을 원천 차단한다.
3. **결정적 검증** — Verifier는 LLM 판단이 아닌 규칙으로 검사한다: 근거 URL 실존 여부, 생성된 할 일 API 재조회, 금지 행동 로그 부재, 90초 타이머.
4. **단일 필수 연동** — 필수 연동은 GitHub 하나. 캘린더는 읽기 전용 ICS로 대체해 완성 위험을 최소화한다.

## 6. Azure 아키텍처

추론은 **Microsoft Foundry 모델 배포**로 통일한다.

| 서비스 | 역할 | 라이브 증거 |
| --- | --- | --- |
| Azure App Service | Next.js 웹 앱·API 호스팅 | 공개 URL에서 Judge Mode 실행 |
| Microsoft Foundry 모델 배포 | 에이전트 추론과 구조화 출력 | 배포 모델과 요청 추적 |
| Azure Cosmos DB | 실행 계약, 영수증, 일별 측정 데이터 | 새로고침 후 복원과 누적 대시보드 |
| Azure Key Vault | GitHub 자격 증명 보호 | managed identity 구성 |
| Application Insights | 단계별 trace와 지연 관측 | `executionId` 단일 trace |

## 7. MVP 범위

### 반드시 구현

- 하루 시작 버튼과 Overnight Diff 수집 (GitHub 실데이터)
- 실행 계약 컴파일과 우선 행동 3개 제안
- 드라이런 미리보기와 노드별 승인·제외
- 할 일 생성 1종 + 이슈 코멘트 초안 1종 실행
- 결정적 Verifier와 증거 영수증
- 일별 시동 시간·절약 시간 누적 대시보드
- Judge Mode (공개 저장소 URL 즉석 실행)
- Cosmos DB 복원, App Service 배포, App Insights trace

### 구현하지 않음

- Outlook 양방향 연동 (읽기 전용 ICS로 대체)
- 메시지·메일 전송, 코드 수정
- 다중 사용자 협업 기능
- 통제 실험 (일별 실사용 데이터로 대체)

## 8. 생산성 측정

| 지표 | 수동 기준 | 목표 | 수집 방식 |
| --- | ---: | ---: | --- |
| 아침 시동 시간 | 30분 | 90초 이하 | 버튼 클릭부터 첫 행동 승인까지 자동 타이머 |
| 확인한 화면 수 | 7개 | 1개 | 클라이언트 이벤트 |
| 첫 유의미 작업 착수 | 40분 후 | 5분 내 | 승인 후 첫 행동 완료 시각 |
| 근거 연결률 | — | 100% | Verifier 규칙 검사 |

수동 기준값은 해커톤 첫날 팀원 4명의 실측 평균으로 확정하고, 측정 로직과 원본 이벤트를 저장소에 포함해 심사 AI가 계산을 재현할 수 있게 한다.

## 9. 책임 있는 AI·보안·신뢰성

- 승인 전에는 어떤 외부 쓰기도 실행하지 않음 (읽기 전용)
- 메시지 전송·코드 수정은 기능에서 원천 제외
- 이슈·PR 본문의 지시는 데이터로 취급 (프롬프트 인젝션 격리)
- 비밀은 Key Vault, 접근은 managed identity와 최소 권한 RBAC
- 동일 노드 재실행 시 중복 생성 방지 (멱등성)
- 실패 노드만 재시도, 모든 실행은 단일 trace로 관측

## 11. 3분 데모

1. **20초:** 첫날 실측한 "아침 시동 30분" 데이터 제시
2. **30초:** 하루 시작 버튼 → Scout 병렬 수집과 도구 호출 실시간 표시
3. **30초:** 실행 계약·드라이런에서 코멘트 초안 노드 하나 제외 후 승인
4. **30초:** 실행과 Verifier 규칙 검사, 증거 영수증 확인
5. **30초:** 누적 대시보드에서 팀원 4명의 일별 시동 시간 추이
6. **20초:** 심사위원 저장소 URL로 Judge Mode 즉석 실행
7. **20초:** 인젝션이 심어진 이슈 본문을 Policy Agent가 차단
8. **10초:** 새로고침 복원과 App Insights 단일 trace

## 12. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| GitHub API 속도 제한 | 조회 캐시와 조건부 요청, Judge Mode는 읽기 전용 |
| 아침 변경이 없는 날 | "변경 없음"도 성공 조건으로 정의하고 오늘의 계획만 컴파일 |
| Judge Mode에서 예상 밖 저장소 | 실패를 숨기지 않고 원인과 부분 결과 표시 |
| 데모 네트워크 장애 | 직전 실행의 영수증·trace를 로컬 재생 가능하게 보관 |

## 13. 구현 순서

1. 세로 흐름: 실제 GitHub 데이터로 수집→계획→승인→실행→검증 1경로 완성
2. 클라우드 증거: Cosmos DB와 App Insights를 초기부터 연결
3. 안전 실패: 승인 없는 쓰기 차단과 인젝션 격리
4. 측정 축적: 일별 자동 측정과 누적 대시보드
5. Judge Mode: 임의 공개 저장소 즉석 실행
6. 완성도: 실행 캔버스 UI와 영수증 정보 밀도 다듬기
