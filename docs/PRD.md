> 매일 아침 하루의 첫 30분을 90초로 컴파일하는 개인 업무 시동 에이전트

## 1. 배경과 문제 정의

### 1.1 대상 사용자

GitHub, 캘린더, 메모를 오가며 일하는 개인 지식 노동자·개발자.

### 1.2 문제

사용자는 매일 아침 업무를 시작할 때 다음을 반복하며 **평균 30분**을 소모한다.

- 어제 어디까지 했는지 기억 복원
- 밤사이 커밋, 이슈 댓글, 리뷰 요청 확인
- 오늘 일정과 가용 시간 파악
- 무엇부터 할지 결정

기존 요약 도구는 정보를 압축할 뿐, "무엇부터 할지"의 결정과 그 준비 작업의 실행까지 연결하지 못한다.

### 1.3 해결 가설

밤사이 변경과 오늘의 제약을 자동 수집해 우선 행동 3개를 근거와 함께 제시하고, 승인된 준비 작업을 실행·검증하면 아침 시동 시간을 **90초 이하**로 줄일 수 있다.

## 2. 제품 목표

| 목표 | 측정 |
| --- | --- |
| 아침 시동 시간을 30분에서 90초 이하로 단축 | `button_clicked`→`approval_completed` 이벤트 자동 타이머 (시동 시간의 유일한 정의) |
| 확인해야 하는 화면을 7개에서 1개로 축소 | 클라이언트 이벤트 |
| 첫 유의미 작업 착수를 40분 후에서 5분 내로 단축 | 승인 후 첫 행동 완료 시각 |
| 모든 제안에 근거 링크 연결 (근거 연결률 100%) | Verifier 규칙 검사 |

수동 기준값(30분, 7개 화면, 40분)은 해커톤 첫날 팀원 4명이 기존 방식으로 아침 시동을 수행하며 단계별 시각과 확인 화면 수를 기록 템플릿에 남긴 실측 평균으로 확정한다. 기록 원본·측정 로직·계산식을 저장소에 포함해 심사 AI가 전후 비교를 재현할 수 있게 한다.

## 3. 핵심 사용자 흐름

사용자 조작은 **버튼 1개 → 승인 1회 → 영수증 확인**의 3단계로 고정한다.

```text
아침 07:50 — 하루 시작 버튼
├── ① 수집: 밤사이 커밋 3, 이슈 댓글 2, 리뷰 요청 1 + 오늘 회의 2건
├── ② 계획: 실행 계약 컴파일 (우선 행동 3개 + 성공 조건 + 금지 범위)
├── ③ 검사: 위험 행동·프롬프트 인젝션 안전 점검
├── ④ 승인: 드라이런 미리보기 확인, 원치 않는 노드 제외
├── ⑤ 실행: 할 일 2개 생성, 이슈 댓글 초안 1개 (승인된 것만)
└── ⑥ 영수증: 성공 조건 5/5 통과, 시동 시간 84초, 절약 28분
```

## 4. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = 시간이 남으면, **N/A** = 명시적 비범위.

## 6. 책임 있는 AI·보안·개인정보

- 모든 AI 제안에 근거 링크를 함께 표시하고, 승인 없는 실행을 금지한다.
- 메시지 전송·코드 수정은 기능에서 원천 제외한다.
- 이슈·PR 본문의 지시는 데이터로 취급한다 (프롬프트 인젝션 격리).
- 사용자 인증은 GitHub OAuth로 처리하고, 사용자별 PAT는 Key Vault에 사용자 스코프 시크릿으로 보관한다.
- 접근은 managed identity와 최소 권한 RBAC로 제한한다.
- 로그에 저장소 본문 전문, 비밀, 개인식별정보를 기록하지 않는다.

## 7. 릴리스 마일스톤

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| M1 세로 흐름 | 실제 GitHub 데이터로 수집→계획→승인→실행→검증 1경로 | E2E 1회 성공 |
| M2 클라우드 증거 | Cosmos DB 저장·복원, App Insights trace | 새로고침 복원 + 단일 trace 확인 |
| M3 안전 실패 | 승인 없는 쓰기 차단, 인젝션 격리, 멱등성 | 차단·격리·중복 방지 테스트 통과 |
| M4 측정 축적 | 일별 자동 측정과 누적 대시보드 | 팀원 4명 일일 실사용 시작 |
| M5 Judge Mode | 임의 공개 저장소 즉석 실행 | 미리 보지 않은 저장소 3개에서 성공 |
| M6 완성도 | 실행 캔버스 UI, 영수증 정보 밀도, 3분 데모 | 데모 리허설 완료 |

## 8. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| GitHub API 속도 제한 | 조회 캐시와 조건부 요청, Judge Mode는 읽기 전용 |
| 아침 변경이 없는 날 | "변경 없음"도 성공 조건으로 정의하고 오늘의 계획만 컴파일 |
