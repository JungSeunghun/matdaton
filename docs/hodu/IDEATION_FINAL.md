# 최종 아이디어: FocusPilot Routine

> 반복 업무를 제시간에 깨우고, 워치 한 번의 승인으로 실행과 검증까지 이어 주는 개인 생산성 에이전트

## 1. 한 줄 요약

평일 아침, 회의 전, 집중 세션 시작처럼 매일 반복되는 일을 루틴으로 등록하면 정해진 시각에 필요한 맥락을 모아 실행 계획을 만들고, 스마트폰·스마트워치에서 승인한 작업만 수행한 뒤 **생산성 증명서**를 발급하는 웹 앱.

## 2. 문제 정의

### 대상 사용자

캘린더, 할 일, 메모를 오가며 비슷한 준비와 확인을 매일 반복하는 개인 개발자와 지식 노동자.

### 핵심 문제

사용자는 하루를 시작하거나 회의를 준비할 때마다 다음을 반복한다.

- 일정, 미완료 업무, 메모 다시 확인
- 오늘 먼저 할 일과 가용 시간 판단
- 여러 앱을 오가며 계획과 타이머 설정
- 끝난 뒤 누락 확인과 다음 날 이월

기존 할 일 앱은 정해진 시각에 알림을 보내지만 맥락 수집, 계획, 승인된 실행, 결과 검증을 하나의 루프로 연결하지 못한다. 그 결과 짧은 반복 업무에도 준비 시간과 앱 전환, 시작 지연이 매일 누적된다.

### 해결 가설

예약 시각에 필요한 정보를 자동 수집하고, 실행 가능한 행동 3개를 제안하며, 스마트워치에서 5초 이내에 승인·연기할 수 있게 하면 반복 업무의 준비 시간과 상호작용 단계를 절반 이상 줄일 수 있다.

## 3. 핵심 사용자 흐름

```text
평일 08:30 — 오늘 업무 브리핑 자동 시작
├── ① 감지: Scheduler가 예약 시각·중복 실행 여부 확인
├── ② 수집: 오늘 일정 3건 + 미완료 업무 5건 + 어제 보류 1건
├── ③ 계획: 우선 행동 3개 + 시간 블록 + 완료 조건 생성
├── ④ 검사: 일정 충돌·민감 정보·외부 변경 위험 확인
├── ⑤ 승인: 워치에서 승인 / 10분 연기 / 휴대폰에서 수정
├── ⑥ 실행: 오늘 보드와 집중 세션 생성 (승인된 것만)
└── ⑦ 증명: 준비 72초, 개입 2회, 시작 지연 3분, 순 절약 11분
```

사용자의 기본 조작은 **자동 알림 → 승인 1회 → 결과 확인**의 3단계로 고정한다. 상세 수정과 근거 확인은 웹 앱, 빠른 승인과 연기는 스마트폰·스마트워치가 담당한다.

## 4. 에이전트 설계

### GitHub Copilot SDK

- 자연어 루틴 생성·수정 대화와 세션 컨텍스트 관리
- `create_routine`, `preview_routine`, `run_now`, `get_run_status` 앱 도구 호출
- 루틴 초안, 실행 상태, 승인 대기 이벤트를 웹 UI에 스트리밍
- 사용자 확인 이후에만 루틴 활성화 또는 즉시 실행
- Copilot 세션 ID를 Agent Framework 실행 ID와 연결

### Microsoft Agent Framework — 5개 에이전트 오케스트레이션

| 에이전트 | 역할 | 만점 증거 |
| --- | --- | --- |
| Context Agent | 일정·할 일·메모를 병렬 수집하고 출처 보존 | 병렬 fan-out trace와 출처 링크 |
| Planning Agent | 우선 행동 3개, 시간 블록, 완료 조건 생성 | 구조화 스키마 출력 |
| Policy Agent | 충돌, 민감 정보, 승인 등급, 금지 행동 검사 | 차단 데모와 정책 로그 |
| Action Agent | 유효한 승인 토큰이 있는 작업만 실행 | 승인 전후 도구 로그 대조 |
| Review Agent | 생성 결과와 완료 조건을 결정적 규칙으로 검증 | 규칙별 통과·실패 증명서 |

```text
Context(병렬) → Planning → Policy → 기기별 사용자 승인 → Action → Review
```

예약 시각 계산, 중복 방지, 기기 선택, 지표 계산은 AI 판단이 필요 없는 결정적 서비스로 구현한다. 모든 단계는 하나의 `runId`로 연결한다.

## 5. 100점을 만드는 4개 장치

1. **Productivity Proof** — 준비 시간, 앱 전환, 사용자 개입, 시작 지연, 완료율을 실행마다 자동 기록하고 Before/After 원시값과 표본 수를 함께 공개한다.
2. **Watch Approval** — 사용자가 앱을 찾아 열지 않아도 워치에서 승인·10분 연기·휴대폰에서 수정 중 하나를 5초 안에 선택한다. 워치 액션 미지원 환경은 모바일 PWA로 안전하게 폴백한다.
3. **Routine Lab** — 심사위원이 시간과 샘플 업무를 바꿔 즉시 실행하면 전체 에이전트 흐름과 결과가 새 `runId`로 생성된다. 고정 화면이나 하드코딩 의심을 차단한다.
4. **결정적 실행 증명서** — Review Agent가 LLM의 주관적 점수 대신 일정 충돌, 생성된 작업 재조회, 승인 토큰, 중복 실행 부재, 완료 조건을 규칙으로 검사한다.

## 6. Azure 아키텍처

추론은 **Microsoft Foundry 모델 배포**로 통일한다.

| 서비스 | 역할 | 라이브 증거 |
| --- | --- | --- |
| Azure App Service | Next.js 웹 앱·Copilot SDK 서버 호스팅 | 공개 URL에서 Routine Lab 실행 |
| Azure Functions | 예약 시각 감지와 실행 메시지 발행 | 예약 시각과 실제 시작 시각 로그 |
| Azure Service Bus | 예약 실행 전달, 재시도, DLQ | 중복 메시지와 실패 복구 데모 |
| Azure Container Apps | Agent Framework API·worker 실행 | 5개 에이전트 실행 trace |
| Microsoft Foundry 모델 배포 | 계획·요약·정책 분류 추론 | 모델 배포명과 요청 추적 |
| Azure Cosmos DB | 루틴, 실행 상태, 승인, 측정 이벤트 저장 | 새로고침 복원과 누적 Proof |
| Azure Key Vault | API 자격 증명과 Push 비밀 보호 | managed identity 구성 |
| Application Insights | `runId` 기반 end-to-end 관측 | 단일 trace에서 전체 단계 확인 |

스마트폰은 PWA Web Push를 수신한다. 스마트워치는 페어링된 스마트폰의 알림 미러링을 우선 활용하며, 운영체제에서 액션을 전달하지 않는 경우 휴대폰 승인 화면으로 연결한다.

## 7. MVP 범위

### 반드시 구현

- 자연어로 평일 08:30 업무 브리핑 루틴 생성·활성화
- 실제 시간 기반 예약 실행과 `routineId + scheduledFor` 중복 방지
- 일정·할 일·메모 샘플 커넥터의 실제 데이터 수집
- 우선 행동 3개, 시간 블록, 완료 조건 생성
- 정책 검사, 드라이런, 승인 후 오늘 보드·집중 세션 생성
- 모바일 PWA Push와 워치 알림 미러링 폴백
- 결정적 Review와 생산성 증명서
- Before/After 누적 대시보드와 Routine Lab
- Cosmos DB 복원, Azure 배포, App Insights trace

### 구현하지 않음

- 이메일·메신저 실제 발송, 일정 삭제, 결제
- Outlook·Google Calendar 양방향 동기화
- 네이티브 iOS·Android·watchOS·Wear OS 앱 동시 개발
- 팀 협업과 조직 단위 생산성 분석
- 10회 미만 표본으로 확정적 향상률 주장

## 8. 생산성 측정

| 지표 | 수동 기준 가설 | 목표 | 수집 방식 |
| --- | ---: | ---: | --- |
| 업무 준비 시간 | 15분 | 90초 이하 | 예약 시작부터 승인 가능한 계획까지 서버 타이머 |
| 상호작용 단계 | 8회 | 3회 이하 | 웹·폰·워치 클라이언트 이벤트 |
| 시작 지연 | 20분 | 5분 이하 | 예정 시각과 실제 세션 시작 시각 차이 |
| 반복 업무 완료율 | 60% | 80% 이상 | 예약 실행 대비 완료 상태 |
| 승인 없는 외부 변경 | 0건 | 0건 | 정책·도구 감사 로그 |

수동 기준값은 해커톤 첫날 팀원들이 같은 아침 준비 루틴을 수동으로 수행해 확정한다. 실제 개선율은 다음과 같이 계산한다.

```text
준비 시간 개선율 = (Before 중앙값 - After 중앙값) / Before 중앙값 × 100
순 절약 시간 = Before - After - 설정 시간 - 검토 시간 - 복구 시간
완료율 변화 = After 완료율 - Before 완료율 (%p)
```

최소 2주 또는 동일 루틴 10회 전에는 “데이터 수집 중”으로 표시한다. 평균만 제시하지 않고 중앙값, 표본 수, 관찰 기간, 제외 사유와 원본 이벤트를 함께 보존한다.

## 9. 책임 있는 AI·보안·신뢰성

- 일정·할 일 조회와 요약은 사전 동의 범위에서만 자동 실행
- 작업 생성·일정 이동은 실행 직전 인자 단위 승인 필요
- 메시지 발송·삭제·결제는 MVP 기능에서 원천 차단
- 워치와 잠금 화면에는 민감한 일정·메모 원문을 표시하지 않음
- 모델 출력은 제안으로만 취급하고 서버 정책과 스키마를 통과해야 도구 호출
- 비밀은 Key Vault, 서비스 접근은 managed identity와 최소 권한 RBAC
- 예약과 도구 호출에 멱등성 키를 적용해 중복 실행 방지
- timeout, 최대 2회 재시도, Service Bus DLQ, 실패 단계별 복구 제공

## 11. 3분 데모

1. **20초:** 수동 아침 준비의 시간·단계 Before 원시값 제시
2. **20초:** 자연어로 “평일 8시 30분 업무 브리핑” 루틴 생성
3. **30초:** Routine Lab 즉시 실행 → Context 병렬 수집과 Agent Framework trace
4. **30초:** 계획 3개와 Policy 검사 결과를 워치 알림 화면에서 승인
5. **30초:** Action 실행 후 Review 규칙별 생산성 증명서 확인
6. **20초:** 중복 메시지를 보내도 작업이 하나만 생성되는 멱등성 데모
7. **20초:** 누적 Proof에서 준비 시간·개입·시작 지연 Before/After 비교
8. **10초:** 새로고침 복원과 Application Insights의 단일 `runId` trace

## 13. 구현 순서

1. 기술 검증: Copilot SDK 서버 호스팅, Agent Framework 구조화 출력, 모바일 Push·워치 미러링 확인
2. 세로 흐름: 아침 브리핑 생성→예약→수집→계획→승인→실행→검증 완성
3. 클라우드 증거: Cosmos DB와 Application Insights를 초기부터 연결
4. 안전 실패: 승인 없는 쓰기 차단, 멱등성, timeout, 재시도, DLQ
5. 측정 축적: 수동 기준선과 실행별 Productivity Proof 자동 기록
6. Routine Lab: 임의 시간과 샘플 업무로 전체 흐름 즉석 재현
7. 완성도: 모바일·워치 폴백과 증명서 정보 밀도 개선
