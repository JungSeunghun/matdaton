# FocusPilot: 개인 업무를 실행 가능한 하루로 바꾸는 에이전틱 AI

## 1. 한 줄 아이디어

FocusPilot은 매일 반복되는 개인 업무를 루틴으로 등록하면 정해진 시간과 상황에 맞춰 준비·실행·확인하고, 스마트폰과 스마트워치에서 최소한의 승인만 받는 개인 생산성 향상 웹 앱이다.

단순한 할 일 추천 챗봇이 아니라, 업무의 맥락을 이해하고 예약·계획·실행·검증을 분담하는 멀티 에이전트 워크플로를 제공한다. AI의 판단과 외부 변경은 위험도에 따라 사용자가 검토하고 승인할 수 있으며, 앱은 절약한 시간과 완료율을 측정해 생산성 향상을 증명한다.

## 2. 해결하려는 문제

개인 개발자와 지식 노동자는 흩어진 메모와 대화를 다시 읽고, 우선순위를 정하고, 큰 업무를 작은 작업으로 쪼개고, 일정 충돌을 확인하고, 하루의 결과를 회고하는 데 많은 시간을 쓴다.

FocusPilot은 이 문제를 “할 일 목록 생성”이 아니라 “반복 업무 실행 루프의 자동화”로 정의한다. 사용자가 매번 앱을 열어 명령하는 구조가 아니라, 루틴이 먼저 실행 시점을 감지하고 필요한 준비를 마친 뒤 적절한 기기로 개입을 요청한다.

## 3. 목표 사용자와 핵심 가치

### 목표 사용자

- 여러 프로젝트를 동시에 진행하는 개인 개발자
- 회의, 문서 작성, 조사 업무가 많은 기획자와 디자이너
- 짧은 기간에 결과물을 만들어야 하는 해커톤 참가자

### 핵심 가치

1. 흩어진 입력을 실행 계획으로 변환해 정리 시간을 줄인다.
2. 모호한 업무를 15~30분 단위의 시작 가능한 다음 행동으로 바꾼다.
3. 관련 메모, 링크, 일정, 결정 사항을 업무의 맥락으로 보존한다.
4. 반복 업무를 시간·요일·일정 이벤트에 따라 자동으로 시작한다.
5. 스마트폰과 스마트워치에서 승인, 연기, 완료를 한 번의 동작으로 처리한다.
6. AI가 임의로 고위험 외부 작업을 실행하지 않고 승인 후 진행한다.
7. 사용 전후 시간, 완료율, 개입 횟수, 재작업 횟수로 개선 효과를 측정한다.

## 4. 핵심 사용자 시나리오

사용자는 매주 평일 오전 8시 30분에 실행되는 “오늘 업무 브리핑” 루틴을 만든다. 루틴에는 캘린더 확인, 미완료 업무 수집, 오늘의 우선순위 3개 선정, 집중 시간 블록 제안이 포함된다.

1. 예약 시각이 되면 Scheduler가 루틴 실행을 시작하고 중복 실행 여부를 확인한다.
2. Context Agent가 일정, 미완료 업무, 메모와 전날 결과를 수집한다.
3. Planning Agent가 충돌 없는 우선순위와 시간 블록을 제안한다.
4. 스마트워치에는 “승인”, “10분 연기”, “휴대폰에서 수정”만 표시된다.
5. 사용자가 승인하면 Action Agent가 저위험 준비 작업을 실행하고 웹 앱에 오늘 계획을 만든다.
6. 사용자는 집중 세션을 진행하고 스마트폰 또는 워치에서 완료·보류를 기록한다.
7. Review Agent가 완료 조건과 실행 결과를 비교해 누락을 표시한다.
8. Reflection Agent가 기준선 대비 절약 시간, 완료율, 개입 횟수와 다음 루틴 개선안을 계산한다.

### 대표 반복 루틴

| 루틴 | 트리거 | 자동 실행 | 기기 개입 |
| --- | --- | --- | --- |
| 오늘 업무 브리핑 | 평일 08:30 | 일정·할 일 수집, 우선순위 제안 | 워치에서 계획 승인 또는 10분 연기 |
| 회의 준비 | 일정 시작 15분 전 | 관련 메모·지난 액션 아이템 요약 | 휴대폰에서 브리핑 확인 |
| 집중 세션 | 승인된 시간 블록 시작 | 방해 금지 제안, 타이머 시작 | 워치에서 시작·일시정지·완료 |
| 하루 마감 | 평일 18:00 | 완료·미완료 분류, 회고 초안 | 휴대폰에서 결과 확인 및 내일 이월 승인 |

웹 앱은 전체 설정, 상세 수정, 근거 확인을 담당한다. 스마트폰은 푸시 알림과 빠른 수정, 스마트워치는 승인·연기·완료처럼 5초 이내의 짧은 상호작용만 담당한다.

## 5. 에이전트 구성

### Context Agent

메모, 일정, 링크, 사용자의 현재 집중 상태를 정리해 업무 컨텍스트를 만든다.

### Planning Agent

목표와 마감일을 바탕으로 완료 조건, 우선순위, 예상 소요 시간, 작업 순서를 제안한다.

### Action Agent

승인된 계획을 작업 카드와 집중 세션으로 변환한다. 외부 변경이 필요한 작업은 사용자 승인을 요청한다.

### Scheduler Agent

루틴의 시간·요일·일정 이벤트를 해석하고 실행을 시작한다. 같은 루틴의 중복 실행을 막고, 실패 시 제한된 재시도와 다음 실행 시각을 관리한다.

### Device Agent

실행 상태와 위험도에 맞춰 웹, 스마트폰, 스마트워치 중 가장 부담이 적은 채널을 선택한다. 워치에는 민감한 원문 대신 요약과 안전한 빠른 동작만 전송한다.

### Review Agent

완료된 작업과 완료 조건을 대조하고 누락·모순·미검증 항목을 표시한다.

### Reflection Agent

하루의 실행 결과를 요약하고 계획 대비 실제 소요 시간, 중단 횟수, 지연 원인을 분석한다.

### 오케스트레이션 원칙

```text
예약/이벤트 감지 → 컨텍스트 정리 → 계획 제안 → 기기별 승인
	→ 작업 실행 → 결과 검증 → 회고 → 다음 루틴 최적화
```

- 각 단계의 상태를 저장한다.
- 에이전트 간 결과는 구조화된 객체로 전달한다.
- 읽기·요약·초안 생성은 자동 실행할 수 있지만 일정 이동, 메시지 발송, 삭제, 결제는 항상 실행 직전 승인을 받는다.
- 실패한 단계는 재시도 또는 사용자 개입 상태로 전환한다.
- 모든 예약 실행은 멱등성 키를 사용해 같은 작업이 두 번 수행되지 않게 한다.

### 필수 기술의 실질적 역할

- **Microsoft Agent Framework**: Scheduler, Context, Planning, Action, Review, Reflection Agent의 오케스트레이션, 도구 호출, 구조화된 상태 전이를 담당한다.
- **GitHub Copilot SDK**: 사용자의 자연어 루틴 생성·수정 대화, 세션 컨텍스트 유지, 앱 도구 노출, 스트리밍 진행 상태를 담당한다.
- **Azure**: 웹 앱 호스팅, 예약 이벤트 전달, 에이전트 실행, 상태 저장, 푸시 알림, 관측과 평가를 담당한다.

화면에 SDK 이름만 표시하거나 패키지만 설치하는 방식은 사용 증거로 보지 않는다. 데모에서는 Copilot SDK 대화가 실제 루틴 도구를 호출하고, Agent Framework 실행 ID로 이어지는 로그를 보여준다.

AGENT1, AGENT2, AGENT3의 합계가 61점이므로 이 세 영역을 제품의 중심으로 둔다. 패키지 설치나 Azure 설정 파일만으로는 증거가 되지 않으므로, 핵심 기능은 실제 에이전트 호출과 실행 로그로 연결해야 한다.

### 감점 상한 규칙 대응

- 증거 없이 설명만 있으면 모든 항목은 배점의 40%가 상한이다. Azure는 실행 증거가 없으면 최대 7.2점, 핵심 흐름이 재현되지 않으면 기능 완성도는 최대 4점으로 제한된다.
- 따라서 데모 재현성과 실행 로그 확보를 기능 추가보다 우선한다.
- 동점 시 AGENT4(기능 완성도)가 AGENT3(Azure)보다 우선 비교되므로, Azure 연동을 늘리는 것보다 핵심 흐름을 끝까지 완성하는 것이 순위에 더 유리하다.

## 7. MVP 범위

### 반드시 구현할 기능

- 업무와 관련 컨텍스트 입력
- 자연어 반복 루틴 생성 및 요일·시간 설정
- 예약 실행, 중복 방지, 실패 재시도
- AI의 완료 조건 및 다음 행동 생성
- 우선순위·예상 시간 기반 하루 계획 생성
- 사용자 승인 및 계획 수정
- 스마트폰 푸시 알림과 워치용 승인·연기·완료 액션
- 작업 상태와 집중 세션 타이머
- 완료 조건 기반 결과 검증
- 하루 회고 및 생산성 지표
- 에이전트 실행 상태, 로그, 오류, 재시도 표시

### 후순위 기능

- 캘린더 양방향 동기화
- 이메일·메신저 자동 수집
- 외부 이슈 트래커에 작업 생성
- 팀 협업 및 공유 대시보드

해커톤 MVP에서는 외부 서비스 동기화보다 하나의 업무 시나리오를 처음부터 끝까지 완성하는 데 집중한다.

## 8. 차별화 기능: Productivity Proof

FocusPilot은 AI가 생산성을 높인다고 주장하는 대신, 실제 사용 기록으로 이를 증명한다.

### 측정 항목

- 계획 생성 시간
- 업무를 다음 행동으로 바꾸는 시간
- 계획된 작업 대비 완료 비율
- 예상 시간과 실제 시간의 차이
- 중단 및 재작업 횟수
- 루틴 1회당 사용자의 클릭·입력·승인 횟수
- 예정 시각 대비 실제 시작 지연 시간
- 자동 실행 성공률과 수동 복구 횟수
- 사용자가 직접 수정한 AI 제안 비율
- AI 사용 전후 동일 유형 업무의 처리 시간

첫 사용 시 기준선을 측정하고 업무 종료 후 같은 지표를 비교한다. 예상치와 실제값을 구분하며, 데이터가 부족할 때는 임의의 향상률을 주장하지 않는다.

### 객관적 Before/After 평가

| 평가 항목 | Before | After | 개선 판단 |
| --- | --- | --- | --- |
| 준비 시간 | 사용자가 일정·메모·할 일을 직접 모으는 시간 | 예약 시작부터 승인 가능한 계획이 나오기까지의 시간 | 중앙값 감소율과 절약 시간 |
| 상호작용 비용 | 클릭, 앱 전환, 직접 입력 횟수 | 웹·폰·워치의 전체 개입 횟수 | 루틴당 단계 수 감소율 |
| 실행 적시성 | 계획 시각과 실제 시작 시각의 차이 | 워치 알림 후 실제 시작 시각의 차이 | 시작 지연 중앙값 감소 |
| 완료 품질 | 누락 또는 재작업이 발생한 횟수 | Review Agent 검증 후 누락·재작업 횟수 | 동일 업무 유형의 오류율 변화 |
| 완료율 | 예정한 반복 업무 중 완료 비율 | 자동 시작된 루틴 중 완료 비율 | 주간 완료율의 절대 변화(%p) |

개선율은 `(Before - After) / Before × 100`으로 계산하되, 완료율처럼 클수록 좋은 지표는 `After - Before`를 퍼센트포인트로 제시한다. 평균만으로 과장하지 않도록 중앙값, 표본 수, 관찰 기간을 함께 표시한다.

### 예상되는 개선과 한계

- 가장 큰 개선 가능성은 정보 수집, 반복 입력, 앱 전환, 일정 확인 같은 준비 단계에 있다.
- 워치의 한 번 승인으로 실행을 시작하면 시작 지연과 스마트폰 체류 시간을 줄일 수 있다.
- 결과 품질은 자동화 자체보다 완료 조건과 Review Agent의 검증 정확도에 좌우된다.
- 초기 설정, 잘못된 알림, 과도한 승인 요청은 오히려 비용을 늘릴 수 있으므로 “순 절약 시간 = 절약 시간 - 설정·검토·복구 시간”으로 평가한다.
- 최소 2주 또는 동일 유형 루틴 10회 전에는 향상률을 확정하지 않고 “데이터 수집 중”으로 표시한다.

### 기준선 측정 방법

- 온보딩 시 동일 유형의 업무 1건을 기존 방식(수동 정리)으로 처리하게 하고 앱이 소요 시간과 단계 수를 타이머로 기록한다.
- 이후 같은 유형의 업무를 FocusPilot 흐름으로 처리한 시간과 자동 비교한다.
- 측정값에는 측정 일시, 업무 유형, 표본 수를 함께 저장해 심사에서 원시 데이터를 제시할 수 있게 한다.

## 9. 웹 앱 화면

### Today

오늘의 목표, 가장 중요한 다음 행동, 남은 집중 시간, 승인 대기 항목을 보여준다.

### Workbench

업무 컨텍스트, 에이전트 제안, 작업 목록, 완료 조건을 함께 보여준다.

### Agent Run

어떤 에이전트가 어떤 도구를 호출했는지, 현재 상태와 재시도 방법을 보여준다.

### Proof

생산성 지표, 계획 대비 실행 결과, 부족한 증거, 다음 개선 제안을 보여준다. 심사에서는 이 화면으로 AGENT2와 AGENT7의 근거를 확인한다.

## 10. 3분 데모 스크립트

1. 고객 피드백을 반영한 온보딩 화면 업무와 메모를 입력한다.
2. Context Agent가 정보를 요약하고 Planning Agent가 4개의 작업과 완료 조건을 생성한다.
3. 사용자가 예상 시간 하나를 수정하고 계획을 승인한다.
4. Action Agent가 오늘의 작업 순서와 집중 세션을 만든다.
5. 한 작업을 완료 처리하고 Review Agent가 누락된 검증 항목을 찾아낸다.
6. 오류 상황에서 재시도를 실행하고 Azure 서비스와 에이전트 흐름 로그를 확인한다.
7. Reflection Agent가 하루 요약과 계획 대비 실제 소요 시간을 생성한다.
8. Proof 화면에서 기존 방식 대비 절약 시간과 부족한 증거를 보여준다.

이 시나리오는 설명이 아니라 실행 가능한 증거로 AGENT1부터 AGENT7까지 연결한다.

## 11. 성공 지표

### 사용자 가치

- 첫 입력에서 실행 가능한 다음 행동이 생성되는 비율: 90% 이상
- 계획 승인까지 걸리는 시간: 2분 이내
- 계획된 핵심 작업 완료율: 기준선 대비 20% 향상
- 업무 정리 시간: 기준선 대비 50% 단축

### 품질 및 안전

- 핵심 데모 성공률: 5회 중 5회
- 모든 외부 호출에 timeout 및 재시도 처리
- 승인 없는 외부 변경: 0건
- 로그의 민감 정보 노출: 0건

발표에서는 목표값이 아니라 실제 원시값, 측정 방법, 표본 수를 함께 공개한다.

## 12. 구현 우선순위

1. 단일 업무의 입력 → 계획 → 승인 → 작업 → 검증 → 회고 흐름
2. 에이전트별 명확한 역할과 구조화된 결과
3. 실행 상태와 도구 호출 로그
4. Azure의 실제 저장·추론·모니터링 연동
5. 생산성 기준선과 전후 비교
6. 오류·재시도·권한·민감 정보 처리
7. 시각적 완성도와 발표용 Proof 화면

## 13. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 에이전트 결과가 매번 달라짐 | 구조화된 출력 스키마, 완료 조건 검증, 고정 데모 입력 |
| 자동화가 사용자 의도와 다름 | 계획 승인과 외부 작업 승인을 분리 |
| 개인 메모에 민감 정보 포함 | 저장 전 마스킹, 최소 권한, 로그 비식별화 |
| Azure 호출 실패 | timeout, 제한된 재시도, 복구 방법 표시, 로컬 fallback |
| 기능 범위가 커짐 | 외부 양방향 동기화보다 핵심 단일 업무 흐름 우선 |
| 생산성 향상 주장이 과장됨 | 기준선·실측값·표본 수를 공개하고 데이터가 없으면 결론 보류 |

## 14. 최종 포지셔닝

> FocusPilot은 사용자를 대신해 무작정 일하는 AI가 아니라, 사용자의 맥락을 이해하고 가장 중요한 다음 행동을 제안하며, 승인을 거쳐 실행하고, 결과로 생산성 향상을 증명하는 개인 업무 운영 시스템이다.

가장 높은 점수를 얻기 위한 핵심은 기능의 개수가 아니라 실제 멀티 에이전트 실행, 측정 가능한 생산성 효과, Azure 연동 증거, 처음부터 끝까지 재현 가능한 사용자 흐름이다.
